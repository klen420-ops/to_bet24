# Форма заказа для Vercel

Эта папка содержит файлы проекта с правильными расширениями. Обработчик отправки восстановлен из исходного проверенного файла.

## Обновление репозитория

1. Распакуйте архив и загрузите содержимое этой папки в корень проекта в GitHub. Не загружайте ZIP как единственный файл.
2. Удалите из репозитория ошибочные файлы `api/catalog.js.txt`, `api/orders.js.txt`, `package.json.txt`, `vercel.json.txt`, если они есть.
3. В корне проекта должны находиться `package.json`, `vercel.json`, `catalog.json`, папки `api` и `public`.
4. В Vercel выберите Framework Preset `Other`. Root Directory должен указывать на эту папку, а не на `public`. Если проект лежит в корне репозитория, Root Directory оставьте пустым.
5. Build Command не требуется. Output Directory задан в vercel.json: `public`.
6. Сохраните изменения и дождитесь Production Deployment со статусом Ready. При необходимости выполните Redeploy после изменения настроек.

## Переменные окружения Vercel

Для Production должны быть заданы:

- `BITRIX_WEBHOOK_BASE` — базовый HTTPS-адрес вебхука с завершающим `/`, без имени метода и параметров запроса.
- `UPSTASH_REDIS_REST_URL` — HTTPS-адрес REST API Redis.
- `UPSTASH_REDIS_REST_TOKEN` — токен Redis с чтением и записью.

Секреты в архив не включены. Существующие настройки Vercel сохраняются при обновлении файлов. После изменения переменных окружения требуется новое развёртывание.

## Проверка

Сначала откройте `/api/catalog` у своего сайта. Ожидается JSON с `ok: true` и массивом `products`.

Затем откройте главную страницу. В ней должны загрузиться товары и цены. Отправка тестового заказа создаёт реальный контакт и сделку с пометкой «ТЕСТ» в Битрикс24.

## Текущее поведение

При каждом новом заказе создаётся новый контакт. Повтор одного request_id блокируется через Redis; успешно завершённый запрос возвращает прежние ID. Частично выполненные запросы повторно не создаются автоматически: после ошибки нужно сверить CRM. Новый request_id считается новым заказом.

В этой версии нет CAPTCHA и ограничения частоты запросов; перед открытием формы для широкой аудитории нужна защита от автоматического спама.

Проверка файлов в архиве выполнялась локально. Публикация и проверка заказов на вашем развёртывании выполняются отдельно.
